# CloudWar 게임 디자인 스펙

- 날짜: 2026-07-07
- 상태: 승인됨 (브레인스토밍 완료)
- 한 줄 요약: 구름으로 하는 땅따먹기 — Agar.io류 질량 경쟁에 극성(+/−) 전투와 비(영토 점령)를 결합한 웹 게임.

## 1. 컨셉

플레이어는 2D 대륙 위 하늘을 떠다니는 구름이다. 수증기를 먹어 질량을 키우고, 비를 내려 땅을 자기 색으로 물들인다. 질량은 전투력이자 영토를 사는 화폐 — "지금 칠할까(작아져서 위험) vs 더 모을까(점수는 0)"가 매 순간의 딜레마다.

구름에는 극성(+/−)이 있다:

- **같은 극성끼리 만나면** 큰 구름이 작은 구름을 잡아먹는다.
- **반대 극성끼리 만나면** 번개가 치며 서로 질량을 잃는 소모전이 벌어진다.

5분 라운드가 끝났을 때 영토율 1위가 승리한다.

## 2. 확정된 핵심 결정

| 결정 | 선택 |
|---|---|
| 플레이 방식 | 3모드 모두 지원. **온라인 멀티·로컬 멀티가 핵심**, 봇 모드는 부수 획득 |
| 플랫폼 | 웹 우선, 데스크톱 + 모바일 모두 지원 |
| 승리 조건 | 구름 그림자(비)로 영토 점령 — 질량(전투력)과 영토율(점수) 이중 구조 |
| 극성 부여 | 스폰 시 선택, 게임 중 스왑 가능 (질량 15% 비용 + 쿨다운 10초) |
| 번개 규칙 | 상호 소모전, 큰 쪽이 유리 (일방적 학살 아님 — 치고 빠지기 가능) |
| 매치 구조 | 5분 타이머 라운드제, 종료 시 영토율 1위 승리 |
| 성장 순환 | 수증기 흡수로 성장 + 비는 질량 소모 |
| 기술 스택 | TypeScript + Canvas 2D + Node ws 서버, 공유 시뮬레이션 코어 |

## 3. 핵심 루프 — 구름, 성장, 영토

### 월드
- 2D 탑다운 대륙 맵. 바닥은 타일 그리드(초기값 128×128). 각 타일은 중립 또는 플레이어 색.
- 구름들은 타일 위 "하늘 레이어"에서 떠다닌다.

### 구름
- 원형 블롭, 질량 `m` 보유. 반지름 ∝ √m.
- 이동속도는 질량이 클수록 감소 (Agar.io 공식 계열).
- 마우스 포인터/터치 방향으로 이동.

### 성장
- 맵에 수증기 알갱이가 지속 스폰. 닿으면 흡수해 질량 증가.

### 영토 점령 (비)
- 버튼/키를 홀드하면 비 모드: 구름 아래 그림자 영역의 타일이 초당 내 색으로 물들고, 질량이 초당 소모된다.
- 구름이 클수록 그림자가 넓어 한 번에 넓게 칠하지만 소모도 크다.
- 상대 타일 위에 비를 내리면 덮어쓰기(탈취) 가능.

### 죽음 / 리스폰
- 질량이 최소치 이하로 떨어지거나 흡수당하면 사망 → 3초 후 시작 질량(START_MASS)으로 랜덤 위치 리스폰. (구현 확정: 최소 질량 리스폰은 즉사 루프라 시작 질량으로 조정, 2026-07-09)
- 리스폰 후 10초간 "안개 보호막": 공격 불가·피격 불가·비 내리기 불가 (스폰킬 방지).
- 사망해도 이미 칠한 영토는 유지되나, 부재 중 뺏길 수 있다.

### 라운드
- 기본 5분. 종료 시 영토율 1위 승리.
- HUD: 실시간 영토율 바 + 남은 시간.

## 4. 극성과 전투

### 극성
- 스폰 시 + 또는 − 선택 (또는 랜덤).
- 시각 구분: +는 따뜻한 톤·위로 솟는 스파크, −는 차가운 톤·가라앉는 입자.

### 극성 스왑
- 키 한 번으로 전환. 비용 = 현재 질량의 15%, 쿨다운 10초.
- 스왑 순간 짧은 방전 이펙트 (무적 없음 — 상대가 읽고 반응할 수 있어야 함).

### 같은 극성끼리 접촉
- 질량 1.25배 이상 크면 작은 쪽을 통째로 흡수 (Agar.io 규칙).
- 1.25배 미만이면 밀려나며 겹치지 않음 — 비슷한 크기끼린 안전.
- 작은 구름의 생존책: 도망 또는 반대 극성으로 스왑.

### 반대 극성끼리 접촉 (번개 소모전)
- 겹친 면적에 비례해 둘 다 초당 질량 손실 (기본: 초당 각자 질량의 ~8%). 번개 이펙트 + 화면 흔들림.
- 손실량의 30%는 물방울 알갱이로 주변에 튀어 제3자가 주워먹을 수 있다 (어부지리 설계).
- 큰 쪽이 오래 버텨 유리하지만, 작은 쪽이 먼저 이탈하면 손실만 입히고 도망 가능.

### 전략 삼각형
- 나보다 큰 같은 극성 = 즉사 위험 → 도망 or 스왑.
- 나보다 큰 반대 극성 = 아프지만 즉사 아님 → 견제 가능.
- 스왑 비용 15% 때문에 남발 불가 → 극성 선택이 심리전.

### 번개 부가효과
- 번개 전투 아래 타일은 3초간 감전 상태 — 누구도 칠할 수 없음.

> 모든 수치(15%, 1.25배, 8%, 30%, 10초 등)는 튜닝 대상 초기값이다.

## 5. 모드 3종과 매치 구조

공통: 한 매치 = 최대 8구름 (플레이어 + 봇 합산), 5분 라운드, 동일 규칙·맵. 인원 부족분은 봇이 자동 충원 — 온라인에서도 대기 없이 시작.

### ① 온라인 멀티 (핵심)
- 방 코드 기반: "방 만들기" → 6자리 코드 공유 → 친구 입장.
- 공개 매치메이킹은 v1 제외 (유저 풀 없이 무의미, 봇 충원으로 대체).
- 서버가 권위(authoritative) 시뮬레이션 실행, 클라는 입력 전송 + 상태 수신·보간 렌더.

### ② 로컬 멀티 (핵심)
- 데스크톱 한 화면 2인: P1 = WASD + Space(비) + E(스왑), P2 = 방향키 + Enter(비) + 우Shift(스왑).
- 화면 분할 없이 맵 전체 조망 (줌아웃 고정 카메라). 나머지 슬롯은 봇.

### ③ 봇 모드 (싱글)
- 서버 없이 브라우저에서 시뮬레이션 코어 실행. 혼자 + 봇 7.
- 연습장이자 밸런스 테스트장.

### 봇 AI (v1)
- 상태 머신 3종: `모으기`(가까운 수증기 추적) / `칠하기`(질량 여유 시 빈 땅에 비) / `회피·추격`(큰 같은 극성 회피, 작은 같은 극성 추격, 반대 극성은 크기 따라 판단).
- 난이도 조절: 반응 속도, 스왑 사용 여부.

### 승리 화면
- 최종 맵 전경 + 영토율 순위 + 재미 통계 1~2개 (예: "가장 많이 번개 친 구름").

## 6. 기술 아키텍처

### 모노레포 구조 (pnpm workspace)

```
CloudWar/
├─ packages/
│  ├─ core/      # 순수 시뮬레이션 (의존성 0)
│  ├─ client/    # Vite + TS + Canvas 2D
│  └─ server/    # Node + ws
```

### core — 공유 시뮬레이션 (프로젝트의 심장)
- 순수 함수형 틱: `simulate(state, inputs[], dt) → state`. DOM·네트워크·타이머 의존 없음.
- 고정 타임스텝 20 tick/초. 렌더링은 클라에서 60fps 보간.
- 결정론 규율: `Math.random()` 금지 → 시드 RNG를 state에 포함. 서버·봇 모드가 완전히 같은 코드로 동작.
- 포함 내용: 구름 이동/충돌, 극성 전투, 흡수, 비/타일 점령, 수증기 스폰, 봇 AI, 라운드 타이머.

### client
- Canvas 2D 레이어 2장: 타일맵(변경 타일만 재그리기) + 하늘(구름·이펙트, 매 프레임).
- 구름 비주얼: 원 여러 개를 뭉친 메타볼 느낌 + 부드러운 그림자. 셰이더 없이 Canvas 그라디언트로 구현.
- 모드별 동작: 봇/로컬 = core 직접 구동. 온라인 = 입력 전송 + 스냅샷 보간 렌더.
- 모바일: 가상 조이스틱(왼쪽) + 비/스왑 버튼(오른쪽).

### server
- Node + `ws`. 방(Room) 하나 = core 인스턴스 하나. 방 코드로 join.
- 20 tick 시뮬레이션, 10 snapshot/초 브로드캐스트 (클라 보간). 타일 변경은 전체 그리드 대신 diff만 전송.
- v1은 클라 예측 없는 단순 모델 (입력 → 서버 반영 → 스냅샷 수신). 지연 보상은 필요해지면 추가.

### 네트워크 프로토콜
- JSON으로 시작 (디버깅 용이), 대역폭 문제 시 바이너리 교체.
- 메시지: `join / input / snapshot / tileDiff / event(번개·흡수·사망) / roundEnd`.

### 배포
- 클라 = 정적 호스팅 (Vercel 등).
- 서버 = Fly.io/Railway류 Node 호스팅 1대. v1은 스케일링 고민 없음.

## 7. 테스트 전략

- **core 유닛 테스트 (Vitest)**: 규칙별 테스트 — "1.25배 이상이면 흡수", "반대 극성 접촉 시 양쪽 질량 감소", "스왑 시 15% 차감 + 쿨다운" 등. 밸런스 튜닝 시 회귀 방지막.
- **결정론 테스트**: 같은 시드 + 같은 입력 시퀀스 → 상태 해시 동일. 서버/클라 코드 공유의 안전장치.
- **통합 테스트**: 헤드리스 봇 8마리로 5분 라운드 완주 시뮬레이션 (승자 결정까지).
- **클라 QA**: 브라우저 QA 도구(/qa 스킬)로 수동·자동 점검.

## 8. 마일스톤

각 마일스톤은 동작하는 결과물을 낸다. M3까지가 재미 검증 구간으로 최우선이며, 네트워크는 core 안정화 후 붙인다.

1. **M1 — 움직이는 구름**: core 골격 + 클라 렌더. 구름 1개 조작, 수증기 먹고 성장. "조작감이 재밌는가"를 여기서 판단.
2. **M2 — 땅따먹기**: 타일맵 + 비 내리기 + 영토율 HUD + 라운드 타이머. 혼자 칠하는 게임으로 성립.
3. **M3 — 극성 전투 + 봇**: 흡수/번개/스왑 + 봇 AI. 봇 모드 완성 — 게임의 재미가 처음 검증되는 지점.
4. **M4 — 로컬 멀티**: 키보드 2인 입력 + 줌아웃 카메라.
5. **M5 — 온라인 멀티**: 서버 + 방 코드 + 스냅샷 동기화. 배포까지.
6. **M6 — 폴리시**: 모바일 터치, 이펙트·사운드, 승리 화면 통계, 밸런스 튜닝.

## 9. v1에서 제외하는 것 (YAGNI)

- 공개 매치메이킹 / 랭킹 / 계정 시스템
- 클라이언트 사이드 예측·지연 보상 (필요해지면 추가)
- 바이너리 프로토콜 (JSON으로 시작)
- 화면 분할 로컬 멀티 (줌아웃 단일 카메라로 대체)
- 지형 다양화 (호수/산 등 — 밸런스 검증 후 고려)
- 구름 분열/합체 (Agar.io의 split 계열 — 극성 스왑이 대체 전략 축)
